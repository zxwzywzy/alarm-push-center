# 随身 WiFi 电话提醒

[返回手册](README.md) · [Windows 分步截图](WINDOWS_PHONE.md) · [OpenWrt 设备与电话](电话提醒与设备工作区.md)

## 使用条件

Windows 客户端和 OpenWrt 后台都可以直接连接 **支持拨号 AT 接口的 UFI-TOOLS 随身 WiFi**。普通 USB 网卡、只上网的热点、任意路由器不能因为填了地址就拨电话。需要 SIM 支持通话、网络就绪、AT 槽位可用、网关空闲且采集端能够访问网关。

手机 App 当前不直接通过随身 WiFi 拨号。电话不是电脑/手机自身的系统通话，也不是第三方云语音服务；当前仅拨号提醒，没有语音播报。

## 一次性配置网关

OpenWrt：进入“系统设置 → 随身 WiFi 电话网关”。Windows：进入设备电话提醒区，再打开网关配置。

| 字段 | 填写 |
| --- | --- |
| 启用网关 | 需要实际拨号才打开 |
| 地址 | 示例 `http://192.168.0.1:2333`，是一个冒号加端口；仅允许采集端可达的私有 IPv4 地址，不带路径、查询或用户名 |
| 原始登录口令 | 填 UFI-TOOLS 的口令原文，不是路由器 root 密码，也不是报警网页管理密码；不要手工散列 |
| AT 槽位 | 0 或 1，按随身 WiFi 实际接口选择 |
| 最长呼叫秒数 | 5～60 秒，默认 25 秒 |
| 两次呼叫最短间隔 | 60～3600 秒，默认 300 秒，多设备共用 |

保存后点“检测连接”。它会认证并读取状态，**不会拨号**。口令留空的保存通常保留已配置秘密；需要换口令时明确填新值。

## 每台设备设置条件

1. 选中要提醒的设备，进入“电话提醒”。
2. 打开启用，填写报警持续秒数（默认 300）和接听号码。
3. 保存该设备，再启用正式采集。
4. 只有该设备有匹配规则的报警持续未恢复、达到阈值且网关可用时，才尝试拨号。

报警恢复、设备断线、停止采集或重新应用配置会取消当前计时。每条持续报警只尝试一次，失败不会无限反复呼叫；多条报警还受全局最短间隔约束。因此“超过五分钟没响”应先看网关状态、采集是否中断、报警是否持续匹配及拨号日志。

## 实际测试电话

1. 先完成检测，使用自己可接听的测试号码。
2. 点击“拨打一通测试电话”，核对弹窗号码再确认。该操作会真实产生呼叫，SIM 可能计费。
3. 看设备返回拨号状态，并由接听端确认响铃/接通；接口返回“拨号中”不等于对方已接通。
4. 按界面结束呼叫或等待最长呼叫时间，检查网关回到空闲状态。

只希望在路由器插随身 WiFi 时使用：保持网关指向该内网地址，断开后检测会失败，不会切换成路由器自行打电话。Windows 则必须让电脑本身能访问该地址。

## 常见错误

| 提示/现象 | 处理 |
| --- | --- |
| 登录口令错误 | 核对 UFI-TOOLS 原始口令；不能用报警页面密码替代；旧版请升级 |
| 网关无法访问 | 浏览器从实际采集端打开同一地址，检查 IP 冲突、USB 网络驱动和路由 |
| AT 槽位无效 / SIM 未就绪 | 核对随身 WiFi 的 AT 接口、SIM 和通话能力 |
| 测试能响，报警不拨号 | 检查当前设备启用、规则匹配、持续时间、保存应用、最短间隔 |
| 显示拨号中但没响 | 看 SIM 呼叫能力、信号、号码和运营商结果；不能只凭 HTTP 成功判断 |
