# OpenWrt 1.5.1 安装、升级与配置指南

> 历史说明：旧安装包保留在私有归档，当前安装与参数以最新手册为准。

发布日期：2026-10-22。适用于 Cudy TR3000 v1、OpenWrt 24.10、软件包架构 `aarch64_cortex-a53`（`mediatek/filogic`）。本次发布为 OpenWrt 网页插件。

[当前安装包与指南](https://github.com/zxwzywzy/alarm-push-center/blob/main/docs/INSTALLATION.md)

## 版本更新

- 每台设备独立管理连接、报警规则与文本、电话提醒、历史。
- 增加“保存此设备”和“一键检查此设备”，保留其他设备尚未提交的修改。
- 修复编辑设备名称后第一次点击顶部按钮无效的问题。
- 连接支持 AT 拨号的 UFI-TOOLS 随身 WiFi 后，可为各设备配置报警持续超时电话提醒。
- 修复 UFI-TOOLS 原始口令正确但认证失败的问题；插件自动完成 SHA-256 转换。
- 保留运行曲线、插件启动开关、邮箱找回和手机 App 配对等功能。

## 首次安装

1. 确认软件包架构为 `aarch64_cortex-a53`，`/overlay` 至少有 35 MB 可用空间，并能访问软件源。本安装包是应用插件，不是刷机固件。
2. 下载 IPK 和同名 `.sha256` 文件，上传到路由器同一目录，例如 `/tmp`，通过 SSH 执行：

```sh
cd /tmp
sha256sum -c alarm-push-center_1.5.1-1_aarch64_cortex-a53.ipk.sha256
opkg update
opkg install ./alarm-push-center_1.5.1-1_aarch64_cortex-a53.ipk
```

依赖由 opkg 安装，包括 OpenSSL、`libopenssl-legacy`、CA 证书及亚洲时区数据。程序自带 .NET 运行时，无需安装 Python 或 .NET SDK。

3. 刷新 LuCI，进入“服务 → 报警推送中心”，点击“启动插件”。首次安装默认不开机自启，也不自动开始采集。
4. 点击“在新窗口打开”，或访问 `http://路由器IP:5080`。
5. 使用首次安装生成的管理密码登录。需要查看该密码时，可通过自己的 OpenWrt SSH 会话执行：

```sh
cat /etc/alarm-push-center/web-password
```

管理密码独立于路由器 root 密码和随身 WiFi 的 UFI-TOOLS 登录口令。

## 从旧版本升级

1. 记录插件开机启动偏好、当前采集状态及“服务启动后自动采集”设置。
2. 备份配置。备份包含现场凭据，应保留在私有存储中：

```sh
umask 077
mkdir -p /root/alarm-backups
chmod 700 /root/alarm-backups
backup_file="/root/alarm-backups/config-$(date +%Y%m%d-%H%M%S).tar.gz"
tar -czf "$backup_file" /etc/alarm-push-center
```

3. 停止插件，再校验并安装新包：

```sh
/etc/init.d/alarm-push-center stop
cd /tmp
sha256sum -c alarm-push-center_1.5.1-1_aarch64_cortex-a53.ipk.sha256
opkg update
opkg install ./alarm-push-center_1.5.1-1_aarch64_cortex-a53.ipk
```

4. opkg 会保留已修改的配置文件；出现冲突提示时保留现场文件。升级不要求更换原管理密码。
5. 按原运行需要从 LuCI 手动启动插件，或执行 `/etc/init.d/alarm-push-center start`。重新登录配置台，核对设备、规则、通知目标和电话设置。
6. 按原采集偏好恢复运行。服务重启会重新开始电话计时，网页会话也需要重新登录。

配置包括设备与规则 `config.json`、启动和找回设置 `console-settings.json`、手机授权 `mobile-devices.json`、电话网关 `phone-gateway.json`；管理密码位于 `web-password`。发布包不包含现场口令、接听号码或机器人凭据。

## 运行与停止

| 位置 | 作用 |
| --- | --- |
| LuCI“启动/停止插件” | 控制网页服务，停止后需要从 LuCI 再启动 |
| LuCI“开机启动插件” | 决定路由器重启后是否启动网页服务 |
| 配置台“系统设置”的采集开关 | 启动或停止当前 PLC 采集 |
| 配置台“服务启动后自动采集” | 决定网页服务启动后是否自动开始采集 |

保存配置只会重新加载正在运行的采集；采集停止时保存仍保持停止。全局“重新加载服务”会重新启动采集。

```sh
/etc/init.d/alarm-push-center status
/etc/init.d/alarm-push-center start
/etc/init.d/alarm-push-center stop
logread -e alarm-push-center
```

## 每台设备单独配置

1. 在“设备工作区”选择一台设备。
2. 在“连接与采集”设置协议、地址、节点或寄存器；高级认证和采样参数按需展开。
3. 在“报警规则与文本”设置该设备的规则，导入 CSV/TSV 字典或 PLC 文本列表。
4. 点击“一键检查此设备”，查看配置、采集连接和已启用电话网关的逐项结果。检查使用草稿，不保存、不发消息、不拨号。
5. 点击“保存此设备”，只提交当前设备和所属规则，其他设备与通知通道的草稿保留。

顶栏“保存并应用”及 Ctrl+S 提交全部页面的草稿。保存后重新加载采集会使所有电话计时重新开始。通知目标和机器人仍在“通知与交互”集中管理。

## 配置超时电话提醒

仅在路由器能访问支持语音拨号的 UFI-TOOLS 随身 WiFi 时可用。普通仅提供上网功能的设备不适用，SIM 也需开通语音业务。

1. 在“系统设置 → 随身 WiFi 电话网关”填写设备地址，例如 `http://192.168.0.1:2333`。
2. 填写 **UFI-TOOLS 的原始登录口令**。不要填写设备后台登录密码、报警插件管理密码或手工生成的散列值。插件自动完成认证转换；留空保留已保存口令。
3. AT 执行槽位先选 0。它是 AT 通道槽位，不一定等于界面的 SIM 卡编号；已验证的 F50 使用槽位 0。
4. 默认最长呼叫等待 25 秒，两次呼叫至少间隔 300 秒，可在“呼叫限制”调整。启用并保存网关。
5. 点击“检测已保存连接”，确认型号、SIM 就绪和当前无通话；此步骤不会拨号。
6. 在当前设备的“电话提醒”启用提醒，填写持续秒数和接听号码，再保存该设备。例如持续秒数为 300，同一报警持续未恢复满 5 分钟才进入呼叫检查。
7. 需要真实验证时，点击“拨打一通测试电话”，核对号码后确认。测试使用当前填写号码和已保存网关，不等待报警超时。

报警恢复、采集断线、停止或重新加载配置后取消等待；每条持续报警只尝试一次拨号。多条报警串行执行并受全局间隔限制，设备忙、网关离线或间隔保护会使呼叫延后。拨号结果不明时不会盲目重拨。当前仅拨号提醒，没有语音播报。

## 密码与邮箱找回

“系统设置”支持修改管理密码、提前绑定找回邮箱和 SMTP 服务。支持 STARTTLS（通常端口 587），不支持 465 隐式 TLS；使用邮箱服务商提供的授权码。

启用并保存找回设置后，忘记密码可在登录页选择邮箱找回。尚未配置邮箱服务时，通过自己的 OpenWrt 管理会话读取 `web-password`。修改配置台密码不修改路由器 root 密码。

## 常见问题

- **正确口令仍提示失败**：确认版本为 1.5.1，刷新页面重新登录，再保存原始 UFI-TOOLS 口令并检测。1.5.0 存在认证转换缺失问题。
- **网页打不开**：先从 LuCI 启动插件；停止插件会同时停止 5080 网页服务。HTTPS LuCI 中选择“在新窗口打开”。
- **电脑能访问随身 WiFi，插件却连接失败**：还需保证路由器本身到该管理地址的网络可达性。
- **检测成功但没有自动打电话**：核对采集运行、设备和规则启用、报警命中规则、电话网关与设备提醒启用，并确认持续时间和全局间隔已满足。
- **OPC UA 仿真离线**：检查 PLCSIM Advanced 外部网卡/虚拟交换机、电脑防火墙、OPC UA 端口以及路由器到仿真地址的路由。
- **需要恢复旧版**：先停止插件，保留配置备份，使用对应旧包及其兼容配置执行回退，不要直接覆盖现有备份。
