# 自动检查与保留配置更新

适用：Windows **1.4.0+**、OpenWrt **1.7.0+**、手机 **1.2.0+**。旧版本没有更新入口，需要先安装一次这些版本；之后不必每次重新填写设备、机器人或手机连接。

## 各端如何更新

| 平台 | 入口 | 更新行为 |
| --- | --- | --- |
| Windows | 顶部“版本更新” | 默认启动时及每 6 小时检查，发现新版提示；点击后下载校验，备份配置，运行 Inno Setup，重新打开并恢复原采集状态 |
| OpenWrt | 系统设置 → 版本更新 | 默认后台检查；可手动“备份并更新”，也可启用维护时段自动安装 |
| 安卓 | App → 连接 → 应用更新 | 前台自动检查，下载校验并核对原安装签名，打开 Android 系统安装确认 |
| iPhone | App → 连接 → 应用更新 | 前台检查，下载并校验未签名 IPA，通过分享菜单保存或交给自签工具；仍需自行签名覆盖安装 |

这是一套应用内更新机制。手机关闭时不接收系统更新推送；重新打开或回到前台会按检查间隔检测。iPhone 自签不能被软件绕过，安卓也不能绕过系统安装授权。[Android 安装权限说明](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())、[Apple 手动安装说明](https://support.apple.com/118254)。

## OpenWrt：一次配置，后续按时更新

1. 升级到 1.7.0 后，打开“系统设置 → 版本更新”，点击检查。
2. 保持“自动检查更新”开启。网络暂时不可用时，旧服务继续运行，不中断采集。
3. 如需无人值守升级，开启“维护时段自动安装”，设置开始、结束小时，填写当前管理密码确认保存。默认维护窗口为路由器本地时间 03:00～05:00；默认不自动安装。
4. 定时任务每 10 分钟查看一次条件，正常每 6 小时查新版本；检查失败约 10 分钟后重试。跨午夜窗口也支持，例如 22～2。
5. 有激活报警、推送排队或电话操作时暂缓；下载完成后会再次检查。更新会带来一次短暂服务重启，并非零停机。
6. 手动更新先保存网页草稿，填写管理密码，再点击“备份并更新”并确认。
7. 页面短暂断开后重新打开/登录即可。网页登录会话可能失效；管理密码和手机配对令牌保留。手机一般无需重新扫码。

### 备份与恢复

- 配置、密码、电话、历史和手机授权：备份到 `/etc/alarm-push-center-updates/config-before-update.tar.gz`。
- 上一个通过健康检查的安装包：`/etc/alarm-push-center-updates/last-good.ipk`，附 SHA256。
- 安装日志：`/etc/alarm-push-center-updates/install.log`。
- 更新阶段与结果：`/etc/alarm-push-center-updates/state.json`，页面会展示结果。
- 安装失败或新版健康检查不通过时，尝试装回 last-good 包并恢复配置；自动回退失败时保留备份并显示需要管理员处理。
- 同一版本自动安装失败/回退后不无限重复尝试，修复问题后可由管理员重新检查并手动更新。
- 保留插件的开机启动开关、自动采集偏好，以及更新前实际采集启停状态。原来停止的采集不会因升级被擅自开启。

更新任务由独立 procd 实例运行，主服务停止不会把更新程序一起结束。当前自动安装仅支持 `aarch64_cortex-a53`；其他架构会拒绝。空间不足或校验失败会阻止安装。只保留一份最近配置备份和最近可用 IPK，避免路由器无限累积包。

插件网页服务关闭时无法后台检查或更新；保持网页服务运行、关闭 PLC 采集，也可以继续查新版本。完整验证范围见[更新验证记录](UPDATE_VALIDATION.md)。

## Windows

先安装一次正式 Inno Setup 版，源码调试目录只提供检查与发布页入口，不能覆盖安装到编译目录。更新窗口可关闭自动检查。

点击“下载并更新”并确认后，下载文件需通过 SHA256；有报警、待发通知或电话操作时暂缓。成功下载后保存当前表单，退出监控，备份独立配置，再更新并重启。安装目录和自定义 `--config` 路径会继续使用，不重置成另一套配置。

本机备份位于 `%LOCALAPPDATA%\AlarmPushCenterUpdates\Backups`；下载与安装脚本位于同目录的版本子文件夹。安装失败时保留 `update-error.log` 并尝试重新打开原程序；Inno Setup 的文件回滚和配置备份不等于任何故障下都能恢复，应保留重要现场备份。

## 安卓与 iPhone

安卓下载后还会检查包名、版本号与签名是否和现有应用一致，拒绝换签、降级和损坏包。首次可能进入“允许此来源安装应用”设置，授权返回后再点更新，已校验的包可复用。**不要先卸载旧 App**，否则本机连接资料可能丢失。

iPhone 下载的仍是未签名 IPA。文件通过 SHA256 后才交给分享菜单，请沿用原来的应用标识和签名身份自签覆盖；不同签名团队/包标识可能无法保留安全存储。更新功能不会上传你的 Apple 账号或自签凭据。

## 以后每次发版的发布流程

1. 分别更新 Windows/OpenWrt 的项目版本、手机 package.json、Android versionCode/versionName 和 iOS 构建号；修改原生包后必须提高原生版本。
2. 更新 [CHANGELOG](../CHANGELOG.md) 与本次配置/安装说明，完成检查并提交源码。
3. 生成 EXE、IPK、同签名 APK、未签名 IPA，为文件生成 SHA256。
4. 按平台标签发布完整附件：`vX.Y.Z`、`openwrt-vX.Y.Z`、`mobile-vX.Y.Z`。手机发布需 APK/IPA 都到齐；建议先建草稿、上传附件，再发布。
5. GitHub Actions **Publish update catalog** 自动从 Release 资产的 SHA256 元数据生成 `updates/stable.json` 并提交 main。附件未齐时会重试；任务失败可在 Actions 中手动重跑。
6. 客户端按各自平台读取正式目录，不会把 OpenWrt 的“Latest”误当 Windows 或手机更新。草稿、预发布、缺少校验值的包不推广。
7. 发布后确认该 workflow 成功，并核对更新目录的版本、文件名、大小和校验值。使用 `node tools/publish-update-catalog.cjs` 也可在已登录 gh 的本机生成目录。

下载只接受本仓库指定命名的 HTTPS GitHub Release 文件，核对大小和 SHA256；不接受任意地址或降级安装。[GitHub Release 资产元数据](https://docs.github.com/en/rest/releases/releases)。安卓还验证安装签名。此机制信任本项目 GitHub 发布账号，不替代账号安全和发布审核。

更新目录优先使用 GitHub Contents API，支持发布者的源码仓库或独立安装包仓库；原生安装包也可从 GitHub Assets API 下载，以减少网页域名不可达的影响。不关闭 TLS 验证，不使用第三方镜像。私有仓库不能让未登录的客户端匿名下载，也不能把发布者私有令牌编进 App；需要公开下载入口或另行配置授权。

本项目采用原仓库公开发布：源码、Release 安装包和 `updates/stable.json` 均在 `zxwzywzy/alarm-push-center`，不要求用户配置 GitHub 令牌。

2026-10-24 公开仓库以干净源码快照重建，网址保持不变；旧仓库保留为私有归档，不迁入历史配置或旧提交。当前三端正式版本和之后的更新使用该公开入口。
