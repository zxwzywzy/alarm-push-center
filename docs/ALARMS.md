## 报警规则

每条规则必须关联一台设备。先选设备，再新增或选择该设备的规则。

| 字段 | 填写与用途 |
| --- | --- |
| 名称 | 便于识别，如“包装线严重报警” |
| 启用 | 关闭后该规则不参与匹配 |
| 报警级别 | 从下拉选择；属于本地规则分类，核对模板中输出值 |
| 匹配报警码 | 留空匹配该设备全部有效码；填写时只匹配指定码 |
| 匹配字段 / 匹配值 | 可选，核对设备自定义字段的值；不需要时同时留空 |
| 冷却秒数 | 抑制短时间重复触发；被抑制事件不会延长窗口 |
| 报警消息模板 | 控制机器人看到的标题、编号、内容和时间 |
| 恢复模板 | 用于恢复事件记录；当前恢复只记录日志/历史，不自动向通知渠道发送 |

从不匹配到匹配会触发；激活期间报警码变化也作为新报警。同一信号匹配多条规则会分别处理，不应靠重叠规则实现“只发一次”。持久在线状态不意味着每次采样都重发通知；冷却也不等于周期提醒。

模板示例：

```text
【{severity}】{source_name}
报警编号：{code}
报警内容：{text}
实例：{instance_name}
时间：{time}
```

可用内置变量：`{source_name}`、`{source_protocol}`、`{source_id}`、`{rule_name}`、`{severity}`、`{code}`、`{text}`、`{time}`。还可引用信号自定义字段如 `{value}`；设备不能覆盖内置同名变量。不存在实例信息的普通协议无需放 `{instance_name}`。

## 报警文本库

文本库属于当前规则，用报警编号覆盖设备默认文本；不要把某台 PLC 的字典直接关联到其他 PLC。可编辑级别/分类、编号、实例名、详细文本，以及 TIA 导入附带的 FB 编号、文本列表名称与索引。

1. 先选设备和规则，再打开文本库。
2. 少量条目直接新增；大量条目用 CSV/TSV 导入。
3. 搜索可查完整字典中的报警码、实例名、文本、FB 与文本列表，不只查当前页。
4. OpenWrt 每页 50 条，支持全选本页或全部搜索结果，翻页保留选择。Windows 提供勾选、全选/取消全选。批量删除前核对数量并确认。
5. 保存设备/配置后才投入正式匹配。删除前建议保留原 CSV，防止选中搜索范围超出预期。

### CSV / TSV 导入

文件使用 UTF-8（可带 BOM），支持标准带引号的逗号与多行文本。Excel 文件请另存为“CSV UTF-8”，不要仅修改扩展名。GBK 文本先转成 UTF-8；乱码不会靠再次导入自动恢复。

简易 CSV 示例，亦可下载 [示例文件](examples/alarm-texts.csv)：

```csv
Category,Code,instance_name,Text
warning,1001,Motor_01,电机温度高
error,1002,Motor_01,电机过载
```

导入后先核对表头映射、编号是否完整、中文、引号和重复项，再保存。程序支持报警字典与 PLC 文本列表两类数据；文本列表还需列表名称、起止索引与文本。不要把文本列表索引误当 AlarmId。

## TIA Openness 导入

仅 Windows 本机扫描 TIA；OpenWrt 导入导出的 CSV。

1. 安装 TIA Portal V21 与 Openness，将当前用户加入 `Siemens TIA Openness` 用户组，重新登录 Windows 使组权限生效。
2. 客户端“报警规则 → 报警文本库”选择“从 TIA ProDiag 导入”，打开 `.ap21` / `.zap21`；或选“读取已打开 TIA”附加现有项目。
3. 首次访问按 TIA 弹窗授权。扫描已有项目只读，不保存、不关闭项目。归档缺 GSD/GSDML 时先在 TIA 修复，优先使用已打开项目入口。
4. 扫描全部设备、PLC、块组及 ProDiag FB，通过 `ExportProDIAGInfo()` 合并监控实例，并用 `PlcAlarmTextListProvider.ExportToXlsx()` 取 PLC 报警文本列表。
5. 检查 CSV 中 AlarmId、实例名、详细文本、FB 名/编号、PLC 名、项目名、优先级、文本列表与索引，再导入对应设备规则。

### AlarmId 和文本不一致时

- 优先按完整 AlarmId。部分服务器返回 Siemens 二进制 Condition NodeId，程序可解析 FB 编号与监控编号进行唯一匹配；多义结果不能靠编号相近来猜。
- `@5%s@: @6%...@` 是关联值模板，运行时需要 A&C 事件中的 AssociatedValue；只看静态导出不一定有最终中文。
- `@4%t#AreaGeneral@` 依赖具体 PLC、FB、监控实例、文本列表及索引。导入会保存相应索引关系；旧数据可能回退到 SD_4。应拿同一实例的一条已知报警和 TIA 显示结果核对，不能全局按行号一一配对。
- 扫描后重新编译/修改过 PLC 项目时，应重新导出匹配字典；旧 AlarmId 不保证仍对应新监控实例。
- 中文乱码先检查导出原文件的编码与语言选择。原文件正确但导入后错误，保留该原文件和一条对应 AlarmId 供排查，不用乱码覆盖正确字典。

保留不了解的原始占位符比错误替换成另一条中文更便于诊断。完整实现细节见 [Windows 使用指南](CLIENT_GUIDE.md#tia-openness-导入-prodiag-文本)。

## 历史报警

1. 进入运行记录/设备历史，选择设备后查询。
2. 显示该设备最近 20 条，每页 10 条，可前后翻页。
3. 记录有报警/恢复状态、编号、文本、级别和时间；当前激活情况仍以实时采集为准。
4. 机器人“历史报警”先展示当前已连接设备，选择后分页查询。手机历史也按设备选择。
5. 清除时确认设备名和范围，按界面完成确认；Windows 清理采用两次确认。此操作不可用浏览器后退恢复，先备份历史文件。

历史位于配置目录的 `alarm-history.jsonl`，超过 5 MB 时保留最近 5000 条。它是有限的本地记录，不是无限期审计数据库。趋势曲线是独立的内存数据，不等于历史文件。
