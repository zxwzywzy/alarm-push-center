# OpenWrt 电话提醒与设备工作区（1.5.1）

> 历史说明：旧安装包保留在私有归档，当前安装与参数以最新手册为准。

[当前安装包与指南](https://github.com/zxwzywzy/alarm-push-center/blob/main/docs/INSTALLATION.md) · [首次安装与升级步骤](releases/openwrt-1.5.1.md)

1.5.1 修复 UFI-TOOLS 登录口令的认证转换：输入原始口令即可，插件会按 UFI-TOOLS 要求自动转换后发送。1.5.0 在口令正确时也可能返回认证失败，建议升级到 1.5.1。

本页介绍 OpenWrt 1.5.1 的电话提醒，需要路由器连接支持语音拨号的随身 WiFi。当前适配 UFI-TOOLS 的 AT 接口，沿用已在 F50 上验证过的拨号方式；普通随身 WiFi 只有上网功能、没有 AT 接口或 SIM 没有语音业务时不能拨号。

Windows 客户端从 1.2.0 起也可直接连接随身 WiFi 拨号，无需经过 OpenWrt 插件；配置入口为“采集源 → 电话提醒”，详见 [Windows 电话提醒](WINDOWS_PHONE.md)。Windows 和 OpenWrt 独立计时，不建议对同一报警同时开启两端电话提醒。

## 一次性配置电话网关

1. 路由器通过 USB 网络、网线或无线中继连接随身 WiFi，保证路由器能访问其管理地址。仅电脑能打开随身 WiFi 页面不代表路由器也能访问。
2. 打开报警插件的“系统设置 → 随身 WiFi 电话网关”。
3. 填写地址，例如 `http://192.168.0.1:2333`，填写 UFI-TOOLS 登录口令。这里不是 OpenWrt root 密码，也不是报警插件管理密码。
4. AT 执行槽位先选 0；这是 AT 通道槽位，不一定等于卡槽界面显示的 SIM 编号。已验证的 F50 使用槽位 0。
5. 默认最长呼叫 25 秒，两次呼叫至少间隔 300 秒；可在“呼叫限制”调整。
6. 启用并保存电话网关，然后点击“检测已保存连接”。检测会检查 UFI-TOOLS、认证、SIM 就绪状态及当前是否有通话，不会拨号。修改口令时留空保留原口令。

口令直接填写原文，插件自动进行认证转换，不要手工改成散列值。填写设备后台登录密码或报警插件管理密码会导致认证失败。使用 1.5.0 时即使原始口令正确也可能报错，应升级 1.5.1，并刷新页面、重新登录报警插件后再检测。

网关设置单独保存在 `/etc/alarm-push-center/phone-gateway.json`，Linux 文件权限为 600。网页查询不返回口令，升级包不携带现场口令。

## 每台设备分别设置

1. 打开“设备工作区”，从唯一的设备选择框选择设备。
2. 在“连接与采集”填写当前设备参数，在“报警规则与文本”维护其所属规则。
3. 打开“电话提醒”，启用此设备的提醒，填写持续秒数与接听号码。例如填 300 表示同一报警持续未恢复满 5 分钟才呼叫。
4. 点击“一键检查此设备”：检查当前草稿的参数、所属规则和采集连接；开启电话提醒时也检查随身 WiFi。检查不会保存、发送消息或拨号。结果按项目显示，修改参数后旧结果清除。
5. 点击“保存此设备”：只提交当前设备和所属规则，其他设备、通知通道的未保存草稿继续保留。“保存并应用”仍会提交所有页面的配置。
6. 需要真实验证时，在“电话提醒”点击“拨打一通测试电话”，核对号码并确认。测试直接使用当前填写号码，不等待报警超时；网关使用已保存设置。

当前实现中，应用设备配置会重新加载采集服务，所有电话计时随之重新开始；此行为会在停止状态下保持停止。

## 触发和取消逻辑

- 只有命中已启用报警规则的激活报警进入计时。按设备和报警码区分，多个规则匹配同一持续报警不会重复呼叫。
- 到达设定时间后，仍须有新鲜采集数据；拨号前再次检查随身 WiFi、SIM 和当前通话状态。
- 报警恢复、采集断线、停止采集或重新加载配置会取消等待；已发起的自动提醒会尝试挂断。
- 网关未连接、SIM 未就绪或设备忙时保留等待，在后续检查中恢复；原有机器人通知照常运行。
- 每条持续报警只尝试一次真正拨号。即使拨号请求超时，也不盲目重拨，以免重复呼叫。恢复后再次出现会重新计时。
- 多条报警共用一个电话网关，串行执行，并受全局最短呼叫间隔限制。因此设定秒数是最早触发时间，设备忙、网关离线或间隔保护时会延后。
- 收到接通状态或达到最长呼叫时发送挂断；请求取消时仍会尝试挂断。若网络断开无法确认挂断，会记录错误，需到随身 WiFi 查看通话状态。
- 目前仅支持拨号/响铃提醒，不包含语音播报。设备接受拨号命令与对方实际响铃、接通是不同结果，界面会区分。

## 验证范围

新增后端测试使用模拟随身 WiFi，覆盖延时、恢复、断线、停止、重复规则、禁用、无网关、占线、全局间隔、取消挂断、权限与输入校验，不会真实拨号。网页交互测试验证设备草稿隔离、单设备保存、检查不拨号和手机布局。

2026-10-22 已在 Cudy TR3000 / OpenWrt 24.10.4 安装 1.5.0，验证 ARM64 程序启动、管理登录、电话接口和关闭状态；原配置内容及开机启动设置保持不变。确认路由器能访问 F50 的 UFI-TOOLS 4.0.5。此前 F50 单独拨号已由接听端确认响铃；完整的“PLC 报警持续超时 → 自动呼叫”链路仍需填写网关口令、启用设备提醒后现场验证。

同日进一步安装 1.5.1 认证修复包，插件只读连接检测返回“已连接 F50，SIM 就绪，当前无通话”，原有配置内容和采集状态保持不变，未进行测试拨号。电话逻辑隔离检查共 41 项通过；完整的 PLC 报警超时自动呼叫仍需按实际设备配置验证。
